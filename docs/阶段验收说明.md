# 个人项目阶段性验收

Git仓库：https://github.com/shiqipzy/campusclaw-coursework

本次在已有CampusClaw增量实现第5/6课。多个助手、提示词模板、知识库检索、内置与上传技能、外部工具/MCP均接入同一应用。PDF包含项目介绍、五个验证问题、真实请求/返回与实际运行截图。

## 五个问题的核对结论

1. **每轮传给LLM什么，模板是否一并传递？** `model=deepseek-flash`、`max_tokens=1200`、`thinking.type=disabled`、`messages`、`stream`。工具决策另带`tools`和`tool_choice=auto`。模板套用后的文字写入助手prompt并进入system，不发送整个模板库。实际返回含`finish_reason=tool_calls`、结构化参数、usage及最终SSE。
2. **是否发送整个知识库？** 否。只检索本班且智能体绑定的材料，最多4个切片、每片800字。资料进user，不进system。无命中仍作答，引用为空。
3. **绑定Skill是否发送全部内容？** 只选至多一个绑定且启用的技能；选中技能的名称及完整说明正文进入system。适用条件、资料与工具字段由宿主作路由/约束。文件原文、其他技能不全量发送。
4. **Skill怎样执行？** 解析中文元数据和正文并入库→绑定→启用候选集→词命中计分→最高分路由，同分较小ID→按说明组装提示→检索/工具编排。上传文本不会被当作脚本运行。
5. **MCP接入后LLM收到什么？** `type=function`、名称、说明、参数JSON Schema。`formula_hint@campus-tools`映射为`formula_hint__campus_tools`。模型提出参数，宿主校验后向独立服务发`tools/call`；MCP地址和令牌不进模型请求。结果以`role=tool`回传，再真实流式生成。
